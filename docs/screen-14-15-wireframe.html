⑥ Behavior, states & edge cases

ConcernSpecReasoning
Persecuted tab routingIf verification_status === 'verified' → render Screen 14. Else → render Screen 14B. Tab is always visible in tab bar.No tab-bar mutation between auth states keeps chrome stable. The screen does the work.
14B toneNo CTA, no toast, no status indicator, no "contact us."Per brief — verification is already underway; the leader has no action to take. The screen is a sealed room, not an error.
KAN-65 scrollWhole screen scrolls (single ScrollView). Feed does not scroll independently.Banner + question + CTA + feed are one continuous read. Independent feed scroll would split the act of witness from its preamble.
KAN-65 empty feedReplace feed cards with single <EmptyHeartcry />: serif italic line "No heartcries have been received yet." + muted body "When the Body brings burdens here, they will appear in this space." Encrypted footer still renders below.Empty state must not feel like a bug — it's a vigil.
KAN-65 → KAN-64CTA "Share Your Heartcry" pushes KAN-64. iOS push transition (no modal).Form is a continuation, not an interruption.
Severity badgeOne-liner pulled from content file per heartcry. Always tag/badge — never inline body text.Per brief — keeps cards scannable + severity legible at a glance.
Card tapOut of scope for this ticket — placeholder press state only (opacity 0.7).Detail view is a separate ticket.
KAN-64 scroll modelSingle-page scroll. No steps, no pagination.Agree with brief. Steps would break the pastoral flow and make the user re-decide to keep going at every threshold. The form is a single act of disclosure.
KAN-64 textareaMin-height 180. Auto-grow with content, capped at ~50% of viewport (~460 pt). After cap, internal scroll.No character count — "There is no limit here."
Witness toggle defaultOFF. Submission is private until user explicitly opts in.Per brief. Witness is an opt-in act, not a default.
Witness toggle visualCard-elevated. Serif label. Subtext below the row. Not styled as <SettingsRow>.Brief: "should feel like an act of witness, not a settings control." Serif label borrows from pastoral voice; sub line names the exact privacy contract.
Submit pressed/loadingDisable button + replace label with "Sending…" Spinner not required. On success: pop to KAN-65 with toast "Your heartcry is with us."Toast in --surface2 above safe-bottom area. (Verify toast token in existing system.)
Overlays / modalsNo expo-blur anywhere. Use black @ opacity 0.72 as scrim.Per brief — performance and aesthetic consistency.
KAN-64 keyboardAvoid keyboard-cover: ScrollView with keyboardShouldPersistTaps="handled". When textarea focused, scroll target = textarea top + 20 pt.User must see what they're writing without dismissing keyboard to scroll.
Tab barPresent on KAN-65. Hidden on KAN-64 (pushed screen).Per brief.
Open items requiring product input
  • Empty-feed copy — the verified-state empty case is not in the content file. Wireframe ships a placeholder; confirm canonical text before ship or omit the empty state and rely on the encrypted footer alone.
  • Confirmation question outcome — wireframe assumes "Share Your Heartcry" goes directly to KAN-64. If "Are you currently undergoing persecution?" is intended as a gate (Yes / No flow), spec a sheet before push. Current build treats the question as voice, not a gate.
  • Severity badge truncation — longest one-liner is "Critical — In immediate danger now" (≈34 chars). At the current badge width this should wrap to a second line on narrowest cards. Confirm wrap vs single-line ellipsis.
  • 14B → 14 transition — when verification completes while the user is on 14B, does the screen swap immediately, on next tab focus, or after relaunch? Default assumption: on next tab focus.
