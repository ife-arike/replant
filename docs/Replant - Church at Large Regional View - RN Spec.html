Context before you start

We evaluated two ways to enter a region — pinch-to-zoom and tap. Tap won; zoom-to-enter is dropped. Pinch on the globe is now only a "look closer" magnifier (1.0–2.4×) with a plain % readout. It does not open anything.

The regional view is the only unbuilt behavior on this screen. Everything around it — globe rotation/pause/resume, RAG dots, the profile sheet, the global prayer pull-up — is done. Wire this into the existing globe; don't rebuild the screen.

01 — The model

Tap a region

The globe rotates slowly. A pill, top-right, always names whichever region is facing the viewer. Tapping that pill — or tapping the globe body itself — opens a right-hand slide-over listing that region's churches. Tapping a church row opens the existing profile sheet. Nothing else changes.

02 — Data model

Regions by nearest center

There is no per-church region field to maintain. Eight macro-region centers are defined; every church is assigned to the nearest center by great-circle distance. Buckets stay self-consistent as churches are added — and the same centers drive "which region is the globe facing."

Assignment + grouping

// great-circle distance in radians (haversine)
function greatCircle(aLat, aLon, bLat, bLon) {
  const r = Math.PI / 180;
  const dLat = (bLat - aLat) * r, dLon = (bLon - aLon) * r;
  const h = Math.sin(dLat/2)**2
    + Math.cos(aLat*r) * Math.cos(bLat*r) * Math.sin(dLon/2)**2;
  return 2 * Math.asin(Math.min(1, Math.sqrt(h)));
}

// each church → the region whose center is closest
function regionKeyForChurch(c) {
  let best = null, bestD = Infinity;
  for (const r of REGION_DEFS) {
    const d = greatCircle(c.lat, c.lon, r.lat, r.lon);
    if (d < bestD) { bestD = d; best = r.key; }
  }
  return best;
}

// regions that actually hold a church, churches grouped in
const REGIONS = REGION_DEFS
  .map(r => ({
    ...r,
    churches: GLOBAL_CHURCHES.filter(c => regionKeyForChurch(c) === r.key),
    underground: UNDERGROUND_REGIONS.includes(r.name),
  }))
  .filter(r => r.churches.length > 0);

Schema note. The prototype computes this client-side from churches.lat/lon. For production, either keep it client-side (cheap, deterministic) or have the API return a precomputed region_key per church and a /regions rollup. See open questions.

04 — Faced-region detection

Which region is the globe facing?

The pill must track the centered region as the globe rotates or is dragged. The contract is the same regardless of rendering engine: the faced region is the region center nearest the point at the front-center of the globe.

Prototype (SVG orthographic globe)

The globe spins in longitude only, so the front-center is (lat 0, lon = lon0). Project each region center and pick the one with the largest z (closest to the camera). Recompute on rotation; fire the change callback only when the region key changes — not every frame.

const faced = useMemo(() => {
  let best = null, bestZ = -Infinity;
  for (const r of REGIONS) {
    const p = project(r.lat, r.lon, lon0); // orthographic
    if (p.z > bestZ) { bestZ = p.z; best = r; }
  }
  return best;
}, [lon0]);

Production (Mapbox globe in React Native)

The SVG globe is replaced by Mapbox's globe projection. There is no z — instead read the camera center coordinate and pick the nearest region center by the same greatCircle(). Debounce on camera idle so the pill doesn't thrash mid-gesture.

// @rnmapbox/maps — on camera change / idle
const { center } = await mapRef.current.getCenter(); // [lon, lat]
let best = null, bestD = Infinity;
for (const r of REGIONS) {
  const d = greatCircle(center[1], center[0], r.lat, r.lon);
  if (d < bestD) { bestD = d; best = r; }
}
if (best.key !== facedKeyRef.current) {
  facedKeyRef.current = best.key;
  setFacedRegion(best);
}

07 — Underground rule

What the panel must never show

Underground churches are not pictured anywhere — not on the globe, not in any list, and not as a row in the regional panel. A region only acknowledges them with the dashed footer.

Flag source. A region's underground flag is true when its name is in UNDERGROUND_REGIONS — currently North Africa, Central Asia, East Asia, Middle East, South Asia. Of the live buckets, that lights up Middle East, South Asia, East Asia.

Counts stay aggregate. The per-region footer is qualitative only — no number. The global +18 hidden count stays in the CAL header chip, exactly as it is today. Do not break the 18 down per region.

08 — Interaction contract

Edge behavior

// pill / globe-body tap
on press(pill)         → openRegion = facedRegion
on tap(globe body)     → openRegion = facedRegion   // no drag, not a dot
on tap(dot)            → openProfileSheet(church)    // region NOT opened
on drag(globe)         → rotate; this is a drag, not a tap → no region open

// panel
on press(row)          → openProfileSheet(church)
on press(close ✕)      → openRegion = null
on press(scrim/back)   → openRegion = null           // Android back closes panel first

// pill label lifecycle
faced region changes   → update pill text only (debounced on key change)
before first resolve   → pill reads "Regions"

// magnifier (unchanged, separate concern)
pinch / wheel          → scale globe 1.0–2.4×, show "NNN%" + Reset
                         NEVER opens a region
09 — Acceptance criteria

Done when

  • The top-right pill names the centered region and updates as the globe rotates or is dragged.
  • Tapping the pill or the globe body opens the centered region's slide-over; tapping a dot opens that church instead.
  • Panel header shows region name + a RAG summary matching the bucket counts in §03.
  • Church rows render name / leader+city / RPL and open the existing profile sheet on tap.
  • Regions flagged underground (Middle East, South Asia, East Asia) show the dashed footer; no underground church ever appears as a row.
  • All 40 fixture churches map into exactly one region — no orphans, counts reproduce §03.
  • Pinch/zoom shows only % + Reset and never opens a region.
  • Panel slides in from the right over ~450ms; close + Android back dismiss it.
10 — Open questions for eng

Decisions to confirm

  • Region sourceCompute region_key on the client from lat/lon (prototype's approach), or have the API return it + a /regions rollup with counts? Client-side is fine for < a few thousand churches.
  • Center vs. lockThe pill always names the live centered region. When the panel is open and the globe keeps rotating, do we keep the opened region pinned (current intent) — confirmed?
  • Panel width on tablet80% reads well on phone. On larger widths, cap at ~420px instead of 80%?
  • Region naming"Asia–Pacific" currently absorbs Oceania + maritime SE Asia (Sydney, Jakarta, Singapore). Keep that label or split?
  • Empty regionRegions with zero verified churches are filtered out today, so they never become "faced." Confirm we never want to surface an empty region's underground footer on its own.
