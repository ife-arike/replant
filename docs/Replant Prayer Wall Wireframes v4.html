Surface 01 · Filter bar

Multi-select filter bar with Urgent stacking

Replaces the single-select pills + separate Urgent toggle. Two semantic groups on one row: Urgent (a tone modifier, red) on the left, then a hairline divider, then the category pills (sky). Both groups multi-select independently. The bar scrolls horizontally on narrow layouts; once ≥1 chip is active a Clear affordance pins to the right edge.

Surface 01 — interaction contract

Every state that changes on tap or scroll

Heart on a card
Passive display only — shows total prayed_count + whether this leader has already pressed it (filled red vs outline). The card heart is not tappable. Pressing happens only inside the detail sheet (below) so the act feels intentional, not accidental.
Tap card body
Opens the bottom-sheet detail (01·F / 01·G). Background: the feed at the leader’s current scroll position, dimmed to opacity: 0.22 with a 55% black overlay + 8 pt backdrop blur. Sheet rises from bottom (320 ms cubic-bezier ease-out).
Detail sheet · Stand in the gap (action state)
Red filled button, outline heart + text. Tap = haptic light tap, button cross-fades to red-ghost variant, the heart in the meta row above fills red, count increments by 1, BE writes prayer_request_prayed_by(request_id, leader_id, prayed_at). When the sheet closes, the underlying card’s heart reflects the new state.
Detail sheet · Stand in the gap (after state)
Red-ghost button, filled heart + “You’ve stood in the gap”. Tap is still allowed — it un-toggles (heart empties, count decrements, BE row deletes). The reverse path is for the leader who tapped by mistake, not an undo-of-prayer; copy stays gentle.
Detail sheet · Connect to this church
If post is not anonymous and not underground-masked: routes to a DM thread with that church’s primary contact, pre-seeded with the prayer request as a quoted reply. If post is anonymous: the CTA renders disabled with "Anonymous · direct message unavailable." No tap action.
Detail sheet · dismiss
Swipe-down on the sheet, tap the ✕ in top-right, or tap the dimmed feed behind. Sheet drops, feed returns to full opacity, scroll position preserved.
Tap idle chip
Chip toggles to selected state (250 ms cross-fade of bg, border, text colour, font-weight). Feed re-queries server with the new filter set. Active-count strip animates in if it wasn't already visible (height 0 → 36 pt, 200 ms ease-out).
Tap selected chip
Chip toggles back to idle (250 ms cross-fade). Server re-query. If this was the last active chip, active-count strip animates out and Clear chip disappears.
Tap Urgent
Stacks with whatever categories are active. Urgent + 0 categories = "all Urgent across categories." Urgent + ≥1 categories = AND logic (Urgent within those categories).
Within-category logic
When ≥2 categories are active, results are an OR within the category set ("posts tagged Healing or Protection"). Urgent is always an AND modifier on top.
Tap Clear
All active chips revert to idle in one frame, active-count strip animates out, feed reloads unfiltered. No confirm dialog — Clear is cheap.
Threshold to 2-row stack
Bar promotes from single-row h-scroll to 2-row stack when 3 or more category chips are active (Urgent doesn't count toward the threshold; it's pinned). Animation: 200 ms ease-out; active chips rise to row 1.
Filter button (top right)
Reserved for a future "advanced filters" sheet — region, date range, leader-name search. Not in v1 scope; the word in the corner is a placeholder for that future affordance, not a duplicate of these chips. If we don't ship the sheet for v1, drop the word so we don't promise a control we don't have.
Scroll feed while filtered
Filter bar and active-count strip remain sticky at top. Feed scrolls underneath them.
Empty result (01·E)
Renders when filter set yields 0 results. Italic serif sentence + mono helper + "Clear filters" pill. The pill acts the same as the bar's Clear chip.
Deep-link / saved filters
Not in v1. If we want it later: encode the active filter set in the URL hash so it survives a refresh / share.
Reduced motion
Drop the 250 ms cross-fades to a 1-frame swap. Keep the row-stack promotion instant. Keep the active-count strip's height animation instant.

Every state that changes on tap or scroll

Tap Prayer Wall tab
Routes to this landing every time (not the feed). The feed lives one tap deeper.
Tap Make intercession CTA
Routes to the feed (Surface 1 with no filters applied). Forward-only — back button on the feed returns here.
Tap Receive intercession CTA · v1
Fires an alert sheet: "Receive intercession is coming soon. For now, your church can request prayer by writing us at [email protected]." Single button: OK. No toast — this is meaningful, not a flash.
Tap Receive · v2 (verified)
Opens the posting sheet (frame 02·D). 4-step wizard: Category → Urgent? → Anonymous? → Compose → Review. Bottom-sheet pattern, swipe-down to dismiss with a confirm-discard guard if any field is dirty.
Tap Receive · v2 (pending)
Same alert as v1, but the message reads "Submitting requests becomes available once your church is verified — you have N days left in your verification window." Reuses the verification copy already in flow 06.
Tap rotator card
Routes to the Testimonies tab (Surface 3) with this specific testimony deep-linked: card expanded, scrolled into view, 1.6 s green glow on its border.
Tap rotator dot
Jumps to that index (manual control). Auto-advance pauses for 12 s after manual control, then resumes.
Swipe rotator left/right
Manual prev/next. Same 12 s auto-advance pause.
Long-press rotator
Pauses auto-advance indefinitely until next tap. Dot strip dims to 50% to indicate pause.
Reduced motion
Auto-advance disabled. Dots remain tappable. Card swap is an instant swap, no cross-fade. Add a small "Next →" tap target in the rotator's lower right.
Tab away & return
Rotator resets to index 0 on every tab visit so leaders always see the newest testimony first.
Rotator pool size
Fetch the 5 newest testimonies on tab-enter; cycle indefinitely until tab leaves.
Zero testimonies
If the server returns 0, the rotator block hides entirely (do not show an empty card). The "See all →" link also hides.
Scroll body
Whole scroll-area scrolls (scripture + action cards + rotator). Top bar and tab bar are sticky.

Surface 03 — interaction contract

Every state that changes on tap or scroll

Tap shofar on a testimony card
Celebrate with them action. One-tap, no expand. The confetti popper icon bursts (0.6 s scale 1→1.2→1.0 + slight rotate ±12°/+8°/−4° keyframes), 6–8 small amber sparkle particles drift up and fade over 800 ms, and the count increments by 1. Haptic light tap. Same per-leader-once toggle pattern — tap again to un-celebrate (popper empties to outline, count decrements). State persists.
Tap testimony card body
v1: no-op (the shofar is the only action on a testimony). v2 (KAN-205 future): opens testimony detail with comments / share.
Tap rotator card (Surface 2)
Navigates to Testimonies tab. The tapped testimony is scrolled-into-view at top, expanded if it has an Originally-posted-as block, and pulses with a 1.6 s green glow. The "From landing" pill appears in the header for 2.0 s then fades.
Tap See all → (Surface 2)
Navigates to Testimonies tab at the top. No deep-link glow. No "From landing" pill.
Tap Feed segment
Switches segmented control to Feed mode. Filter bar reappears. Scroll position resets to top. State of filter chips is preserved across mode flips (so if leader had Healing+Urgent active, that survives a trip into Testimonies and back).
Tap Testimonies segment
Switches to Testimonies mode. Filter bar replaced by the scripture header. Testimonies feed loads.
Tap testimony card
v1: no-op (the celebrate-shofar in the meta row is the only interactive element). Visual ripple feedback only (200 ms rgba(green, 0.10) flash) on tap-down. v2 (KAN-205 future): opens testimony detail with prayer count, comments, share.
Pull-to-refresh
Standard iOS pattern. Refresh icon tinted green. Refetches the page-1 testimonies.
Filter button (top right)
In Testimonies mode, opens a future filter sheet for region / time range / category-of-original-request. Out of scope for v1; the word "Filter" is dimmed if the sheet isn't shipped.
Scroll near bottom
Auto-fetch next page of 10. Skeleton card placeholder while loading.
Reduced motion
Drop the glow and pill fade animations. Instead, render a 3 pt green outer ring on the deep-linked card (static) and keep the pill visible until next tap.
Underground masking
Out of scope for this design — RPC enforces masking and FE never re-derives it. Card shows whatever location field the server returns (which may be "Anonymous · <region>").

Surface 04 · My open prayers

My open prayers — edit, delete, mark as praise

Reached from the View my open prayers link on the landing (Surface 02). Lists every open request submitted by anyone in this leader’s church — not just this user’s account, so co-leaders see the same list. Each card carries an overflow menu (Edit · Mark as praise · Delete). Marking as praise opens a composer that quotes the original request above the testimony body — the same “Originally posted as:” treatment used for deep-linked testimonies in Surface 03.

Surface 04 — interaction contract

Every state that changes on tap or scroll

Tap View my open prayers
Navigates from landing (Surface 02) to this list. Header reads My open prayers; count in top-right shows total open. Empty state: italic serif “Your church has no open prayer requests yet.”
Scope of “my”
Church-wide, not user-wide. Lists every open request from any leader at this user’s church (leader-1 + leader-2 + any co-leader). Author shown in meta row (“by Pastor Daniel”).
Tap overflow trigger
Opens popover anchored to trigger. Tapping outside dismisses without action.
Tap Edit
Opens the v2 posting sheet (frame 02·D) pre-populated with the current request’s category, urgent flag, anonymous flag, and body. CTA reads Save changes. Save updates the post in place; intercessors who already prayed are not re-notified.
Tap Delete
Fires the confirm dialog (04·C). Cancel dismisses with no state change. Delete soft-deletes (per D-01): row marked is_active=false, removed from the wall, but retained for audit / scrub.
Tap Mark as praise
Opens the praise composer (04·D) with the original request quoted in the green-tinted block. Leader writes the testimony body, optionally toggles anonymous, submits.
Submit praise
Posts a new Testimony record linked to the original request via original_request_id. Original flips to status=answered and disappears from this list. App routes to Testimonies tab (Surface 03), scrolls to the new testimony with a 1.6 s green glow + “Just posted” pill.
Anonymous on praise
If toggled on, the testimony renders with the church masked to “Anonymous · <region>”. The Originally posted as: quote is also masked for self-consistency.
Cancel composer
If textarea is empty, dismiss without confirm. If textarea is dirty, show a “Discard testimony?” confirm with the same shape as the delete confirm.
Pull-to-refresh
Refreshes the list. Catches co-leader posts from another device.
Empty state
Centered serif italic “Your church has no open prayer requests yet.” + 0.5 pt rule + a green ghost button Receive intercession → back to the landing’s Receive card. (In v1 that path is locked; show the same lock affordance.)

Project-wide rules established in this pass

Add to the design system doc

Scripture never truncatesAnywhere scripture appears in the app — landing scripture-of-the-day, Testimonies header, devotional banners, splash quotes — render the full verse. No ellipsis, no “redacted for space.” If it doesn’t fit at the current type scale, drop the scale until it does, or break the verse across more lines, or move it to a calmer position. Truncating scripture is a hard no.
Card uniformityAll prayer-request cards in feed views share a uniform body height via line-clamp: 3. Long content trails to … and the card is tappable to a detail bottom sheet. Chevron › in meta signals tappability. (My-open-prayers cards drop the chevron and use the overflow menu instead.)
Connect-to-this-church availabilityDirect-message CTA is enabled only when the post is not anonymous and not underground-masked. In all other cases the button renders disabled with explicit copy: “Anonymous · direct message unavailable.”
Action-card weightHero action cards on landings (Make / Receive) render at 30 pt Cormorant weight 500 with a 30 pt icon circle. These are doors, not chips.

Open questions for product

Resolve before CC starts the build

Filter button
Top-right "Filter" word: ship a future advanced-filters sheet, or drop the word for v1?
Rotator pool size
Confirmed 5 newest testimonies on tab-enter — or do we want a curated set (e.g., featured by an admin)?
Receive intercession v1 copy
Alert text: "Receive intercession is coming soon. For now, your church can request prayer by writing us at [email protected]." — sign off?
Categories v1 set
Six chips: Healing · Protection · Unity · Provision · Praise · Manpower. Lock the set or add a 7th?
Testimony posting (KAN-205)
Wireframe sketched at 02·D — not in this brief's deliverable scope. Track separately?
Anonymous label for verified leaders
When a verified leader posts anonymously, does the card show "Anonymous · <region>" or just "Anonymous"? Underground masking rules clarify, but anonymous-by-choice may behave differently.
Receive intercession icon
v4 swap to a glass less than half full (vessel with low water-line, awaiting fullness). Pairs with the rising-incense bowl on Make — one rising, one waiting to be filled. Replaces the chalice / plant-being-watered explorations.
Celebrate icon
v4 swap from shofar to a confetti popper (🎉 — cone + confetti specks). Reads clearly at icon scale and pairs with the tap-burst animation. Alternatives if it still doesn’t land: a more illustrated shofar, clap, or a dove with olive branch. Say the word.
Celebrate · secondary action?
Open. The user asked whether the celebrate tap could trigger something more than just counting. Candidates: (1) a small “send a kind word” bubble that lets the leader attach a one-line note to the celebration; (2) a tiered “celebrate / amen / glory” picker on long-press; (3) just the count + sparkle, nothing else. Default ship is (3) for v1 — calm, fast, doesn’t pull the leader out of scroll. Flag if you want (1).
“Stand in the gap” server semantics
v3: per-leader-once toggle. Tap fills heart, increments prayed_count by 1, persists. Tap again un-toggles, decrements. Count is total all-time, not windowed. Need BE shape: prayer_request.prayed_count + prayer_request_prayed_by join table keyed on (request_id, leader_id).
Praise-report visibility
When a leader marks a request as praise, the testimony appears in the public Testimonies tab. Confirmed — or is there a moderation step?
