Closing the gate — two-factor that actually holds from the first moment

Today every admin session sits at AAL1 and every per-action second-factor check rejects, because nothing ever elevates the session after the password. This CD designs the two surfaces that fix the UX layer of that gap: a full-screen enrollment gate an admin can't get past without a verified authenticator, and a step-up modal that re-challenges with a TOTP code — not the password it used to re-probe — before a destructive action lands. Built on the live rp-* system. No new tokens.

Father, this is a small gate guarding people we will never meet — underground leaders whose safety rests on an admin's session being exactly as strong as we claim it is. Let no session sit weaker than we believe. Make the seams hold, and make our copy honest: clear, unshowy, never coddling competent people, never leaking a name. Where these sit in the sign-in flow

Two surfaces, one enforcement

After this work, signInWithPassword no longer lands an admin on the dashboard at AAL1. If a verified factor exists, the inline TOTP challenge elevates the session. If no factor exists, Surface 1 stands in the way until enrollment completes. Surface 2 is the per-action re-challenge that mints a short-lived, action-bound token — and it asks for a code, because re-entering the password only re-proves what the session already proved by existing.

Why a code and not the password
Re-entering the password proves the admin knows the same secret the session was opened with — it establishes nothing new. A TOTP code proves possession of the second factor right now. That is the whole point of step-up, and it's the pattern Stripe / GitHub sudo-mode / Okta / Atlassian all settled on. The user-facing copy never says "AAL2," "step-up," or "elevation" — admins are told plainly to confirm with their code.

Surface 2 · StepUpTotpModal

Step-up, re-challenged with a code

Triggered by a destructive action — here, rejecting an underground verification. The modal names the action, takes a 6-digit code, and runs the same state machine the approved TotpChallengeModal uses: idle → verifying → error → locked (5 attempts, 15-minute cooldown). Use View as to inspect each state. Cancel returns to the queue with nothing rejected.

Token contract (for the implementing engineer)
On a passing code: challengeAndVerify establishes second-factor possession, then the step-up token mints — bound to the (user_id, action) pair, 5-minute TTL, separate from session freshness, single-use against that one action to prevent replay across a different destructive call. CD does not wire mfa.challenge/verify; onVerified(token) hands the token back to the caller that opened the modal.

Every string, and why

Voice: clinical, peer-respecting, honest about mechanism. Admins know what TOTP is — nothing is coddled, nothing euphemised. Italic stays reserved for scripture; none is forced onto an auth surface.

Surface 1 — welcome framing
title"One more step before you're in." Universal — shown to new invitees and factor-reset admins alike. Alt for Founder pick: "Finish setting up your account."
sub"Replant admins must sign in with an authenticator code. Set yours up to continue."
why (card)The access justification lives in the card, now universal (not Heartcry-specific, since the screen also hosts profile re-enroll): "Admin access reaches sensitive information about leaders in restricted contexts. Two-factor authentication is required before you continue."
recovery"…contact the Replant Operations team at accounts@projectreplant.org to restore access. There is no automated recovery."
foot"Every admin enrolls before reaching the dashboard. There's no skip." — honest about the gate, no drama.
Surface 2 — step-up
title"Verify your identity" — matches TotpChallengeModal exactly, so the two re-challenges read as one system.
sub"Enter the 6-digit code from your authenticator app to confirm this action."
action"You're about to reject underground verification UG-A540. This can't be undone." — action named, consequence stated, ref carried.
error"Incorrect code — N attempts remaining before 15-minute lockout." (verbatim from TotpChallengeModal)
locked"Too many attempts. Try again in 15 minutes. The action was not performed." — the added clause reassures nothing fired.
Banned, per the voice ruling
No "Oops!", no "Copy it somewhere safe", no exclamation reassurance. No "AAL2," "step-up," "elevation," "freshness," "JWT" on any user-facing string. Red is used only on the destructive-action context line and error/locked states — never on a headline.
