Flipping visibility, with a human on the other end of the line

A verified underground leader decides to change whether their church is Hidden or Visible in the network. Because that flip is exactly the moment an adversary would want to forge, the change can't be a toggle — it routes through a scheduled confirmation call with the admin team and a 4-digit code the leader speaks aloud. This CD designs the six mobile surfaces that carry the leader from the request to the outcome, the security floor on the live call, and the duress channel hidden inside how the code is read.

How the path runs

One request, one call, one outcome

The flip is hybrid leader-initiated: the leader asks, schedules a safe window, the admin claims the slot, a silent push lands at T-15, the leader pre-arms by tapping I'm ready, and the admin dials. The code only exists on screen during the call, and only the leader's voice carries it across. Everything else — screen-capture blocks, idle blanking, the duress reverse — defends the few minutes it is visible.

The six surfaces
01 entryInside Settings → Church. Current state + "Request to change to [VISIBLE | HIDDEN]". Renders only for underground churches.
02 scheduleExplainer + window picker. The leader chooses when they'll be somewhere safe to talk.
03 briefingOne-shot safety briefing the first time only — teaches the over-shoulder defenses and the reverse-the-digits duress signal.
04 lobbySurfaces at T-15 off root. Schedule recap + "I'm ready" to pre-arm the call.
05 activeThe code, large + mono. Hide-code target, idle blanking, duress jog, delayed / validating states.
06 completeEndgame copy — success either direction, or the "didn't connect" failure with a fresh picker.
State machine — VisibilityChangeRequest
pendingLeader scheduled a window; admin hasn't claimed the slot yet.
revealedAdmin claimed; T-15 reached; leader has opened the lobby.
in_callLeader tapped "I'm ready"; admin dialed; code is on screen.
validatedAdmin entered the correct (or reversed duress) code; visibility flipped.
expiredTTL elapsed with no validation; force re-mint via a new window.
failedToo many wrong attempts; admin must re-mint. Leader sees only the terminal outcome.
Why a call and not a toggle
The load-bearing promise is that a hijacked session or a coerced leader can't quietly change what the network shows. A confirmation call puts a human anti-social-engineering check in the path: the admin confirms it's really the leader before the flip lands, and the 4-digit code proves the person on the call is the one holding this phone. Brute-force defense is per-attempt audit + AAL2 + lockout, not entropy — four digits is enough because every guess is logged against a live, rate-limited call.

Surface 03 · FirstCallSafetyBriefing · one-shot

The briefing, shown once

The first time a leader reaches a live call, this stands in front of the code for a moment. It teaches the three things the active screen can't say out loud every time: the screen guards itself, the code never leaves by any channel but their voice, and — the load-bearing one — if anyone is forcing this, read the digits in reverse. After this, the active screen carries only a quiet jog. Shown once per leader, then never again.

Every string, and why

Voice: clinical, peer-respecting, never coddling. No "Oops!", no "copy it somewhere safe", no exclamation reassurance, no auth-internal vocabulary leaking to the leader. Italic is reserved for scripture — none is forced onto these utility surfaces, so the endgame lines render roman even though the brief quotes them in italics.

No "Oops!", no "Copy it somewhere safe", no exclamation reassurance. No "TOTP" / "AAL2" / "token" / "duress" surfaced to the leader. No greens and no celebratory flare on the flip — success tracks state with sky / muted, never a green checkmark. Italics never used for emphasis on any screen here.
For Founder ratification

Open questions

Q1Window-picker granularity. CD shows 2-hour blocks per the panel ruling. Alternatives: 30-minute slots (tighter, but implies a precision the call doesn't need) or leader-defined free time. CD lean → keep 2-hour blocks. Founder confirm.
Q2Does the leader see who the admin is? CD shows nothing — no admin name, no avatar — to keep the surface symmetric and leak-free. Alternative: a generic "Replant team member". Founder ratify.
Q3Surface the call channel? CD assumes a plain phone call and shows no number or link. If the call is in-app voice or a dialed number, the lobby + active screens need a channel line. Founder direct.
Q4Duress reminder frequency. CD puts the plain teaching in the one-shot briefing and only a coded jog on every active render. Alternative: the jog appears first-call only. CD recommends → coded jog every call (muscle memory matters under stress; the jog is innocuous to an observer). Founder ratify.
Q5Reversibility asymmetry. Onboarding makes Visible → Hidden never self-reversible (admin-only). This flow puts both directions behind the same call. Confirm that's intended for already-verified leaders — i.e. a verified leader may self-initiate going Hidden again via this call, unlike the onboarding lock.
